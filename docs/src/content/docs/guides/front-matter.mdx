The `InsertFrontmatter` toolbar button adds front-matter, or opens it for editing. If the dialog
closes before new front-matter is saved, it is removed again. The form keeps
values such as `false`, `0` and empty strings when another field changes, and saving without
changes keeps the original YAML, comments and formatting included. Structured and multiline values
are kept but can't be edited in the form; front-matter that the form can't edit safely must be
changed in the source.

Pass `FrontmatterEditor` to replace the form. It receives the `yaml` (without the `---`
delimiters) and an `onChange(yaml)` callback, and can follow `frontmatterDialogOpen$`. Call
`onChange` before closing the dialog, so a new block is kept.

The default form's YAML rules are exported for your own form, so it handles values the same way:

| Function                              | Does                                                                                   |
| ------------------------------------- | -------------------------------------------------------------------------------------- |
| `parseFrontmatter(yaml)`              | The top-level `entries`, and `invalid` for YAML a key-value form can't edit safely     |
| `serializeFrontmatter(entries)`       | YAML without the delimiters; entries without a key are dropped                          |
| `frontmatterEntriesEqual(a, b)`       | Whether nothing changed, so you can keep the original YAML and its comments            |
| `frontmatterValueText(value)`         | The text a field shows for a value                                                     |
| `frontmatterFieldValue(text, value)`  | The value to save: the original one, with its type, while the text is unchanged        |
| `isFrontmatterValueEditable(value)`   | `false` for lists, maps and multiline strings, which a single-line field can't edit    |
